# Kenney Toon Characters — import & animation guide (CAT105TC)

Source: [Kenney](https://kenney.nl) "Toon Characters" pack — **CC0 / public domain**.
Free for personal, educational and commercial use. Crediting Kenney is optional but appreciated.

This folder is the shared character art for the labs — the W3 lab uses the single `idle`
frame (W3 has no animation yet), the **W4 lab** (`Assets/Scenes/W4Lab.unity`) turns it into
a full flip-book animation. It is the exact same set of sprite frames you can hand to
students so everyone animates the same character.

---

## 1. Folder layout

```
KenneyToonCharacters/
  Male person/
    PNG/
      Poses/          <- 45 ready-to-use frames, e.g. character_malePerson_walk3.png
      Parts/          <- body parts (head, arm, leg ...) if you want to assemble your own pose
      Poses HD/       <- 2x resolution versions
    Tilesheet/        <- character_malePerson_sheet.png + .xml  (one atlas with all 45 frames)
    Vector/           <- the original .svg
  Female person/  Female adventurer/  Male adventurer/  Robot/  Zombie/    <- same structure
```

Six characters ship with the pack. The lab uses **Male person**; swapping is one constant
(see §6).

---

## 2. The frames the animation uses

| Clip  | Frames                                        | Notes                       |
|-------|-----------------------------------------------|-----------------------------|
| Idle  | `idle`                                        | 1 frame                     |
| Walk  | `walk0` … `walk7`                             | 8 frames, loop              |
| Run   | `run0`, `run1`, `run2`                        | 3 frames, loop              |
| Jump  | `jump`                                        | 1 frame, no loop            |
| Fall  | `fall`                                        | 1 frame, no loop            |

All frames are **96 x 128 px**, the character's feet sit on the **bottom edge** of the canvas.

## 3. Import settings (the ones that matter)

| Setting | Value | Why |
|---|---|---|
| Texture Type | **Sprite (2D and UI)** | otherwise it imports as a Texture and `SpriteRenderer` can't use it |
| Sprite Mode | Single (poses) / Multiple (tilesheet) | |
| Pixels Per Unit | **96** | a 96x128 frame becomes ≈ 1 world unit tall, matching the 1-unit platforms |
| Pivot | **Bottom Center** | the feet are on the bottom edge, so `transform.position` is "where the feet are" |
| Mesh Type | Tight (default) | |
| Mip Maps | **off** | 2D sprites don't need them |
| Alpha Is Transparency | **on** | clean edges when scaling |
| Filter Mode | Bilinear | the toon art is smooth, not pixel art |
| Compression | Uncompressed (for a small pack) | avoids artifacts on flat colours |

These are applied automatically by `Assets/Editor/KenneyToonCharacterImporter.cs`
(an `AssetPostprocessor`), so you never have to click through 677 textures by hand.
**If you move the art to another project, copy that one file too** — or set the six rows above manually.

## 4. Animation plan (what to tell students)

### 4a. The five AnimationClips

Create them with **Window ▸ Animation**, or let this project build them automatically —
they are generated by `Assets/Editor/W04_AnimationCamera/CharacterRig.cs` and saved to
`Assets/Animations/W04_AnimationCamera/` (menu ▸ **CAT105TC ▸ W04 Animation & Camera ▸ Build W4 Lab**).

| Clip | Frame rate | Loop | Curve |
|---|---|---|---|
| `Player_Idle` | 8 | ✔ | `SpriteRenderer.m_Sprite` = idle |
| `Player_Walk` | 12 | ✔ | walk0 → walk7, one key per frame at `i/12 s` |
| `Player_Run`  | 14 | ✔ | run0 → run2 |
| `Player_Jump` | 8 | ✘ | jump |
| `Player_Fall` | 8 | ✘ | fall |

A sprite flip-book is a **single "Sprite" curve** on `SpriteRenderer.m_Sprite` — one
object-reference keyframe per frame. Frame *i* sits at time `i / frameRate`.

### 4b. The AnimatorController (`Assets/Animations/W04_AnimationCamera/Player.controller`)

States: **Idle, Walk, Run, Jump, Fall** — default state **Idle**.

Parameters:

| Name | Type | Driven by |
|---|---|---|
| `Speed` | float (0..1) | how fast we *want* to move ÷ max speed |
| `VerticalSpeed` | float | `Rigidbody2D.velocity.y` |
| `IsGrounded` | bool | the downward `Physics2D.Raycast` |
| `Jump` | trigger | fired the instant we apply the jump impulse |

Transitions:

| From → To | Condition | Notes |
|---|---|---|
| Idle → Walk | `Speed > 0.05` | exit time off, duration 0 |
| Walk → Idle | `Speed < 0.05` | |
| Walk → Run  | `Speed > 0.60` | |
| Run → Walk  | `Speed < 0.60` | |
| Any → Jump  | `Jump` trigger | "Can Transition To Self" **off** |
| Any → Fall  | `IsGrounded` = false **and** `VerticalSpeed < -0.1` | catches jumps *and* walking off ledges |
| Fall → Idle | `IsGrounded` = true | Idle → Walk then takes over |

### 4c. Driving it from code (`PlayerController2D.cs`)

```csharp
animator.SetFloat("Speed",         Speed01);         // 0..1
animator.SetFloat("VerticalSpeed", rb.velocity.y);
animator.SetBool ("IsGrounded",    grounded);
if (jumpHappened) animator.SetTrigger("Jump");
```

Note the slide point: those are *Animator* parameters, not C# fields — change them every
frame in `FixedUpdate`, and the Animator picks the clip.

## 6. Reusing a different character

1. Pick one of the six folders, e.g. `Robot`.
2. In `Assets/Editor/Common/LabKit.cs` change:

```csharp
public const string CharacterArtFolder = "Assets/Art/KenneyToonCharacters/Robot/PNG/Poses";
// and in CharacterSprite():
... + "/character_robot_" + pose + ".png"
```

3. Re-run **CAT105TC ▸ W04 Animation & Camera ▸ Build W4 Lab**
   (and **CAT105TC ▸ W03 Physics2D ▸ Build W3 Lab**).

Note: the animation is **W4 lecture content**, which is why the clips and the
AnimatorController live under `Assets/Animations/W04_AnimationCamera/` and are built by
`Editor/W04_AnimationCamera/CharacterRig.cs`. The W3 lab presents the character without an
Animator on purpose — animation had not been taught yet.

## 7. A gotcha worth teaching

Animating `Transform.m_LocalPosition` on an object **clears the axes you did not key** —
animate a child ("Visual") if you want the parent to stay put. The `PropertyDemo` object in
W4Lab is built exactly this way. It is the animation-overrides-code lesson from the slide,
made concrete.
